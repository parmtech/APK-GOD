# Source review record — APK-GOD 0.2

Review recorded on **2026-11-12**. This file identifies twenty reference projects and the specific material inspected in the available local source snapshots. It is a targeted API and architecture review, not a full audit of every repository, algorithm, rule, platform or dependency.

## What was actually inspected

The reference workspace contains Git commit identities and selected materialized source files. The files linked below were read in bounded excerpts: declarations, headers, docstrings, API boundaries and selected entrypoint bodies. Their local blob hashes were checked against their recorded Git commits. Several checkouts contain only selected materialized files; the existence of a Git tree does not establish that all source or submodules were downloaded or reviewed. Frida's core and Gum subprojects were not present as populated source trees in this inspection.

These are source-study snapshots, not dependency version pins. APK-GOD's installed engines and versions are listed in [../pyproject.toml](../pyproject.toml) and [../THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). In particular, the inspected Androguard reference snapshot has a newer parser-facade layout than the installed 4.1.3 API used by APK-GOD. Reviewing one does not validate the other.

## Relationship to APK-GOD's implementation

The package imports installed Androguard APIs for APK/DEX/resource parsing and Java-like reconstruction, LIEF and Capstone for native structures and instructions, optional angr/Claripy for native models, and optional Frida APIs for explicitly requested runtime observation. The product supplies its own job handling, bounded intermediate records, evidence graph, reports, UI, export management and optional AI projection. See [../ARCHITECTURE.md](../ARCHITECTURE.md) for the implemented module boundaries.

The source study highlights separate engineering problems: parsing an APK, recovering high-level code, assembling/rebuilding it, collecting runtime evidence, collecting network traffic and interactively debugging native code. Success in one of these does not establish support for the others. The reference list therefore maps to the explicit implemented slices and remaining work in [CAPABILITIES.md](CAPABILITIES.md), rather than a count of twenty completed integrations.

The downloaded reference trees are study material outside the APK-GOD package. Listing a project here is not a claim that all of its code has been incorporated, that its capabilities are reproduced, or that its licensing has been replaced. APKiD rules, GPL reference scanners, complete debuggers and application patch/rebuild engines are not presented as part of the original MIT framework. Conversely, installed engines and their transitive dependencies remain third-party software even when called through one APK-GOD interface.

## Limits of the record

- No full source audit, clean-room certification or complete dependency/binary licensing certification was performed.
- No benchmark against all twenty tools established superiority, equivalent accuracy, equivalent coverage or lower resource use.
- Reading entrypoints is not validation of runtime behavior. Automated tests and recorded fixture runs belong in [VALIDATION.md](VALIDATION.md).
- Source reconstruction is inspection output. This review does not establish recovery of original source, original names, server implementations or a buildable application project.
- The Frida native binary, all Frida subprojects, every processor backend and every transitive dependency were not individually audited.
- Future code reuse or modification must retain the relevant provenance, license text, notices and other applicable terms. Refactoring or optimization does not remove those requirements.
